# 0G usage map

Every 0G integration in 0run, mapped to the exact code and to the on-chain evidence. Ordered by how load-bearing it is: remove any of the first three and the product stops existing.

We also register every coach on ERC-8004's own IdentityRegistry (`0x8004A818…`, already live on Galileo, not our contract — ABI confirmed against the reference implementation and cross-checked live via `eth_call` before any code was written, see `docs/decisions.md`), tying our AgentNFT tokenId to it as on-chain metadata: [tx `0x8b571001…`](https://chainscan-galileo.0g.ai/tx/0x8b571001e567be0bb27c8650fc819b3fcb1e5dea54f9ed1057c634fa6fde9c40) → ERC-8004 agentId 148, `getMetadata(148,"0run.tokenId")` reads back `"3"`.

Rather than ship something undeployable we wrote a minimal ERC-7857-shaped contract with the subset we use. The whole investigation, including the failing deploy trace, is in `docs/decisions.md`.

## 0G Storage — encrypted data, hashed locally

| What | Where |
|---|---|
| Upload / download with a receipt (never throws, never fabricates) | `apps/web/src/lib/zerog/storage.ts` — `uploadEncrypted`, `downloadDecrypted` |
| Hash locally, upload separately | same file — `prepareEncryptedUpload` |
| SDK-level encryption (`aes256`) on top of our own envelope | same file, `realDeps()` |
| Our AES-256-GCM envelope | `apps/web/src/lib/crypto/aes.ts` |
| Key derived from a wallet signature (never persisted) | `apps/web/src/lib/crypto/keys.ts`, `apps/web/src/lib/client/useUserKey.ts` |
| GPX stored per run | `apps/web/src/lib/coach/pipeline.ts` (step `store_gpx`) |

`prepareEncryptedUpload` exists because of something we measured rather than assumed: the merkle root of the encrypted stream is computable locally, so the on-chain commitment does not have to wait for an upload that took **22+ minutes to become readable** and, in one case, never returned at all. Every SDK call is now bounded by a timeout, and a timeout says explicitly that the on-chain submission may still have landed — because that is what we observed. See `docs/0g-reality-check.md`.

## 0G Compute — the coach's reasoning, with proof of use

| What | Where |
|---|---|
| Router adapter (OpenAI-compatible) with model fallback | `apps/web/src/lib/inference/router.ts` |
| Direct broker adapter with per-response attestation (`processResponse`) | `apps/web/src/lib/inference/direct.ts` |
| One interface over both, plus schema-validated JSON with retry | `apps/web/src/lib/inference/index.ts` — `coachComplete`, `completeJson` |
| Prompts: personality + profile in system, run + history in user | `apps/web/src/lib/coach/prompts.ts` |
| Report generation | `apps/web/src/lib/coach/pipeline.ts` (step `inference`) |
| Chat, with an optional run pinned into context | `apps/web/src/app/api/coach/chat/route.ts` |

Measured on the real network: `glm-5.2`, valid JSON first try, 19.5s, 1274 output tokens of which 789 were reasoning. `x_0g_trace` carries the provider address `0x7DCFe6AEa70350C2090041524c9B4A9262DCe87D`, request id `13eed4ff-2b82-4418-b241-392708839536`, and the on-chain cost — that trace is our proof that inference ran on 0G Compute and was paid for.

We only select TEE-attested providers. Where attestation is genuinely unavailable the UI says so instead of claiming it: `verifiedTee` is `boolean | null` and the report shows *"attestation not available"* (`apps/web/src/components/run/report-view.tsx`).

## Not used, on purpose

**0G DA** serves rollups building on top of 0G; it has no role in this product. Wiring it in to appear thorough would have been noise. **The 0G KV store** was evaluated and rejected: its public node was unreachable when tested (2026-07-25), so mutable metadata lives in Postgres — which, as an index rebuildable from Storage plus chain, is honest about what it is.
